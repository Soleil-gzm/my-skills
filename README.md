# My Skills 项目

这是一个包含多个技能（skills）的项目集合，每个技能都针对特定的开发任务提供自动化支持。

## 项目结构

```
my-skills/
├── git-commit/          # Git 提交助手技能
├── project-doc-writer/  # 项目文档编写技能
└── README.md            # 本文件
```

## 技能详情

### git-commit

Git 提交助手技能，用于分析 git 变更并生成规范的 Conventional Commits 提交消息。

#### 功能特点

- **安全检查**：在提交前检查敏感文件，防止机密信息泄露
- **智能拆分**：当变更涉及多个不相关模块时，自动生成拆分计划
- **规范消息**：生成符合 Conventional Commits 标准的提交消息
- **执行确认**：在执行提交前向用户展示计划并确认
- **卫生防护**：检查 .gitignore 配置，防止构建产物等文件被提交

#### 核心原则

1. **diff 是唯一事实来源**：必须基于 git diff 来生成提交消息
2. **一个 commit 一个目的**：无关变更应该拆分成多个提交
3. **敏感文件绝不入库**：提交前会检查并排除敏感文件
4. **执行前必须给用户看计划**：确认后才执行提交操作
5. **禁用 `git add -A` / `git add .`**：逐文件添加，防止带入无关文件

#### 使用场景

当用户说"提交/commit/帮我写 commit message/这些改动怎么拆 commit"时使用。

#### 语言约定

- **subject（第一行）：英文**，使用祈使语气，整行 ≤50 字符
- **body（正文）：中文**，解释 what/why，不解释 how
- **type 选择**：按变更的主要目的选择，优先级为 `fix > feat > refactor > chore`

#### 标准流程

1. 收集状态（只读）
2. 安全与卫生检查
3. 判断要不要拆分
4. 写消息
5. 确认并执行

### project-doc-writer

项目文档编写技能，用于生成和维护项目文档。

#### 功能概述

该项目文档管理技能能够根据不同的使用场景，自动识别并加载相应的文档生成和管理策略。它支持以下五个核心场景：

1. **场景① 规划**：为新项目生成规划文档
2. **场景② 冷启动**：为无文档项目生成初始文档结构
3. **场景③ 生成/重构**：生成或重构文档结构
4. **场景④ 同步/保鲜**：同步代码变更与文档更新
5. **场景⑤ 解释**：解释架构和设计决策

#### 核心原则

- **先读代码再写文档**：从 `package.json`、`pyproject.toml` 等文件中读取项目信息，避免编造功能
- **README 是落地页**：80-120行，包含项目介绍、安装、使用示例和文档链接
- **改现有文档前必须给计划**：列出要修改的内容，等待用户确认
- **使用项目的语言**：保持与现有文档风格一致
- **保持现有风格**：标题层级、表格风格与现存文档一致

#### 文档结构

项目会生成以下标准文档结构：
```
README.md               # 落地页，80–120 行
docs/
├── getting-started.md  # 必有：安装、启动、验证
├── architecture.md     # 有清晰架构时
├── api.md              # 暴露 API 时
├── configuration.md    # 有环境变量/配置文件时
├── deployment.md       # 有 Dockerfile/CI 时
├── contributing.md     # 开源/团队项目时
└── testing.md          # 有测试套件时
CHANGELOG.md            # 留在根目录
```

#### 技术栈支持

支持多种技术栈的自动识别和文档生成，包括：
- Web 框架：Django、FastAPI、Flask、Express、NestJS、React、Vue、Next.js、Angular
- 后端语言：Spring Boot、Rails、Python/Rust/Go/JS 库
- 基础设施：Terraform、K8s、Docker、Ansible
- 全栈项目
